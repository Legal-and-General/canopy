## Usage

Use the details component to hide secondary information like FAQs and supporting details to make pages easier to scan.

Import the details components into your application:

```js
import { LgDetailsComponent } from '@legal-and-general/canopy';
```

and in your HTML:

<Source of={DetailStories.StandardDetails} />

Information that is important or relevant to most users should not be included within this component and should be displayed on the page instead.

The component has **not** been designed for large amounts of information or rich content (sound, video, etc). It should only be used for small amounts of content. It can be used to contain Link components alongside text, if required.


The Details component can also be styled to match the [inline message component](./?path=/docs/components-inline-message-alert-guide--docs) with `warning`, `info`, `success` and `error` colouring. This lets you highlight information in different ways depending on severity.  
**These statuses should be used sparingly; the generic status should be suitable for most situations.**


## How it works

The details component combines an icon, label and chevron within a container. Clicking anywhere within the container will expand or collapse the content within. Content should be collapsed by default.

The "alert" ARIA role is automatically added to the component if it's one of these statuses: `warning`, `error`, `success`. Note that this role will tell the browser to send out an accessible alert event to assistive technology products which can then notify the user about it.

A decorative icon is also added next to the heading for all statuses: `generic`, `info`, `warning`, `error`, `success`.
For `generic` and `info`, the icon can be customised. For `success`, `warning`, and
`error`, the icon remains fixed.

## Additional development details

### Inputs

| Name           | Description                                                                                            | Type      | Default   | Required |
|----------------|--------------------------------------------------------------------------------------------------------|-----------|-----------|----------|
| `isActive`     | Expand the details                                                                                     | `boolean` | `false`   | no       |
| `headingLevel` | The level of the details heading: `1`, `2`, `3`, `4`, `5`, `6`                                         | `number`  | n/a       | Yes      |
| `status`       | Applies status treatment and ARIA role if applicable: `generic`, `info`, `warning`, `error`, `success` | `string`  | `generic` | No       |
| `showIcon`     | Whether the status icon should display                                                                  | `boolean` | `true`    | No       |
| `icon`         | Custom icon for `generic` and `info` statuses only                                                      | `IconName`| `globe`   | No       |

### Outputs

| Name     | Description                               | Type                 | Default | Required |
|----------|-------------------------------------------|----------------------|---------|----------|
| `opened` | Event emitted when the details are opened | `EventEmitter<void>` | n/a     | No       |
| `closed` | Event emitted when the details are closed | `EventEmitter<void>` | n/a     | No       |

***

## Research on this pattern

This component is based on best practice and has not had specific usability testing.

More research to be conducted into whether the error state should be deprecated, as the details component may not be a suitable for errors.
