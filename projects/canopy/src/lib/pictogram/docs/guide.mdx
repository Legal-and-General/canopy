# Pictogram

<p class="standfirst">A pictogram allows you to add supporting illustration to messages or journeys.</p>

Adding a pictogram can provide extra affordance and help users in making decisions or understanding the outcome of a journey.

More illustrative and colourful than UI icons, pictograms draw attention, create narratives and help to visualise data.


*Design guidance for this component is currently being rewritten. Please contact the Canopy team if you need more information on how to use this component.*
## Usage

Consider using the message with illustration pattern for the end of journeys and for empty states.

Import the pictogram component in your application:

```js
import { LgPictogramComponent } from '@legal-and-general/canopy';
```

In your HTML:

```html
<!-- with default size and no fill -->
<lg-pictogram name="sun"></lg-pictogram>

<!-- with fill enabled -->
<lg-pictogram name="sun" [hasFill]="true"></lg-pictogram>

<!-- with a status fill -->
<lg-pictogram name="confirm" [hasFill]="true" status="success"></lg-pictogram>

<!-- with a size set -->
<lg-pictogram name="sun" size="sm"></lg-pictogram>
```

### Fill and colour

Pictograms are unfilled by default. Set `[hasFill]="true"` to use the theme's
default fill colour.

#### Optional status

When a pictogram supports a status message, you can optionally set `status` to
reflect the type of message:

| Status | Use for |
|--------|---------|
| `info` | Information |
| `success` | A successful action or outcome |
| `warning` | A warning or interrupted service |
| `error` | An error preventing progress |

Set `[hasFill]="true"` to show the status fill; otherwise the pictogram remains
unfilled. The status leaves the outline unchanged. Omitting or clearing `status`
restores the theme's default fill when `hasFill` remains `true`.

### Pictogram names

Use `notification` and `notification-confirm` for the notification artwork. These
replace `bell` and `notification-bell` respectively; the previous names are no
longer available.

The catalogue also includes `coins`, `pounds-confirmation`, `pounds-decrease` and
`pounds-warning`.

### Sizes

Pictograms should be scaled according to the following sizes to ensure outlines look clean and crisp.

|                    | **rem** | **px** |
|--------------------|---------|--------|
| `--lg-pictogram-sm`  | 10      | 160    |
| `--lg-pictogram-md`  | 12.5    | 200    |
| `--lg-pictogram-lg`  | 15      | 240    |
| `--lg-pictogram-xl`  | 17.5    | 280    |
| `--lg-pictogram-xxl` | 20      | 320    |

## Dos and Don'ts

### Do


* **Do** scale pictograms according to the sizing chart above.
* **Do** enable `hasFill` when using a pictogram in a self-service application only, to make the fill visible on neutral backgrounds.

### Don't


* **Don't** use a pictogram in place of a UI icon, or at a size less than 160px.
* **Don't** set `hasFill` to `true` to fill pictograms when using them in highly-branded scenarios such as in the Dotcom CMS.

## Additional development details

### Inputs

| Name   | Description          | Type            | Default     | Required |
|--------|----------------------|-----------------|-------------|----------|
| `name` | The name of the icon | `string`          | `undefined` | yes      |
| `size` | The size of the icon | `sm,md,lg,xl,xxl` | `sm`        | no       |
| `hasFill` | Applies a fill | `boolean` | `false` | no |
| `status` | Sets the pictogram status | `'info' \| 'success' \| 'warning' \| 'error'` | `undefined` | no |
