## Usage

Use the side nav for related pages within an account or service. Wrap the entire
layout in one content area, with the side nav inside `lg-content-area-content`.
The side-nav components provide layout and focus handling, not a card surface.

Import the components and Angular router directives in your standalone component:

```typescript
import { Location } from '@angular/common';
import { inject } from '@angular/core';
import { RouterLink, RouterLinkActive, RouterOutlet } from '@angular/router';
import {
  LgButtonComponent,
  LgContentAreaComponent,
  LgContentAreaContentComponent,
  LgContentAreaHeaderComponent,
  LgColourDirective,
  LgIconComponent,
  LgLinkMenuComponent,
  LgLinkMenuItemComponent,
  LgLinkMenuItemTextComponent,
  LgSideNavComponent,
  LgSideNavBarComponent,
  LgSideNavBarFooterComponent,
  LgSideNavBarLinkDirective,
  LgSideNavContentComponent,
} from '@legal-and-general/canopy';
```

Add these components and directives to your component's `imports`, then compose
the pattern in its template:

```html
<lg-content-area lgColour="blue" lgColourTheme="neutral">
  <lg-content-area-header>
    <button lg-button type="button" priority="link" (click)="back()">
      <lg-icon name="arrow-left" />
      Back
    </button>
  </lg-content-area-header>
  <lg-content-area-content>
    <lg-side-nav>
      <lg-side-nav-bar label="Account navigation">
        <lg-link-menu>
          <a
            routerLink="overview"
            routerLinkActive
            #overview="routerLinkActive"
            ariaCurrentWhenActive="page"
            [isActive]="overview.isActive"
            lgSideBarNavLink
          >
            <lg-link-menu-item>
              <lg-link-menu-item-text [isBold]="true"
                >Personal details</lg-link-menu-item-text
              >
              <lg-link-menu-item-text>
                Name, date of birth and marital status.
              </lg-link-menu-item-text>
            </lg-link-menu-item>
          </a>
          <a
            routerLink="contact"
            routerLinkActive
            #contact="routerLinkActive"
            ariaCurrentWhenActive="page"
            [isActive]="contact.isActive"
            lgSideBarNavLink
          >
            <lg-link-menu-item>
              <lg-link-menu-item-text [isBold]="true">Contact</lg-link-menu-item-text>
              <lg-link-menu-item-text>Your contact information.</lg-link-menu-item-text>
            </lg-link-menu-item>
          </a>
        </lg-link-menu>
        <lg-side-nav-bar-footer>
          <button lg-button type="button" priority="secondary" (click)="logout()">
            Logout
          </button>
        </lg-side-nav-bar-footer>
      </lg-side-nav-bar>
      <lg-side-nav-content>
        <router-outlet />
      </lg-side-nav-content>
    </lg-side-nav>
  </lg-content-area-content>
</lg-content-area>
```

Configure the corresponding routes in your application. `RouterLink` changes the
URL and renders the selected page in the outlet. `RouterLinkActive` drives the
current item, including direct route entry and browser back/forward navigation.
When a link becomes active, the side nav moves focus to the content region.

The header contains only the back action and is optional. Omit it when no back
action is needed; omit the navigation footer when there is no secondary action.
Your application supplies the back and logout behaviour. For example:

```typescript
private location = inject(Location);

back(): void {
  this.location.back();
}
```

Choose an appropriate destination when there is no previous page in the application.
Implement `logout()` using your application's authentication service.


## Dos and Don'ts

### Do

1. **Do** use one content area around both navigation and routed content.
2. **Do** give the navigation a meaningful label and mark the current link with `aria-current="page"`.
3. **Do** use link-menu text components for labels and optional descriptions.
4. **Do** retain `lg-side-nav-content` as the focus target for routed content.

### Don't

1. **Don't** wrap the side nav or its panels in cards or nested content areas.
2. **Don't** manually track a clicked index instead of using the router's active state.
3. **Don't** place the logout action inside the link menu; use the navigation footer.

## Additional development details

### Responsive layout

At `64rem` and above, the navigation sits on the left and routed content on the
right, using nominal `1:2` flex proportions. Below this breakpoint, the navigation
sits underneath the content. The layout fills the available content-area width;
it does not impose a fixed minimum page width or an exact 12-column grid.

The optional header contains the back action only.

### Routed content spacing

The side nav provides a content-area content section for each column. Do not add
another content-area wrapper inside `lg-side-nav-content`.

Routed component hosts and their directly nested forms use a column layout with
`--content-area-gap`. Their immediate children's block margins are reset so field
components do not add their default bottom margin to the gap. This does not reset
spacing inside fields, hints or validation messages. Additional nested groups must
provide their own layout; the rule does not apply to every descendant form or field.

### LgSideNavBarComponent inputs

| Input   | Description                                | Type     | Default | Required |
| ------- | ------------------------------------------ | -------- | ------- | -------- |
| `label` | Accessible name for the navigation region. | `string` | `'Nav'` | No       |

### LgSideNavBarLinkDirective inputs

Apply `lgSideBarNavLink` to each navigation anchor within the link menu.

| Input      | Description                                    | Type      | Default | Required |
| ---------- | ---------------------------------------------- | --------- | ------- | -------- |
| `isActive` | Whether the link represents the current route. | `boolean` | `false` | No       |

### LgSideNavBarLinkDirective outputs

| Output      | Description                                                                                  | Value                |
| ----------- | -------------------------------------------------------------------------------------------- | -------------------- |
| `activated` | Emitted when `isActive` is set to a truthy value. Used by the side nav to focus its content. | `EventEmitter<void>` |

### Existing navigation items

The existing `LgSideNavBarItemComponent`, `LgSideNavBarItemHeadingComponent` and
`LgSideNavBarItemContentComponent` exports remain available for existing templates.
Use link-menu components for new side-nav layouts.
